# 人机协同岗位制衡框架
> 这是一套**治理范式、工作规则**，不是封装好一键运行的Agent，是一颗供人自主修改、实践的种子。

## ✨ 核心思想
很多AI协作的痛点，根源不是模型不够强：
- AI擅自发散、私自扩充需求
- 自审自查存在天然盲区，幻觉很难被自己发现
- 人在流程里慢慢失去主导权

本框架的核心思路：**岗位物理隔离，禁止实现岗兼任审查；人牢牢握住起头权、需求过滤权、最终决策权。**
它不绑定任何特定大模型、API、部署方案。实现岗、审查岗可以自由选择付费API、免费额度应用等，由使用者根据自身场景决定。

## 📜 不可动摇核心铁律
1. 实现岗（输出岗）只负责按照明确需求产出内容，**不承担自我审查、校验、复盘工作**
2. 审查岗独立于实现岗，二者完全隔离，禁止同会话自审
3. 所有任务的发起、需求边界定义、需求膨胀拦截、结果验收，决定权归人
4. 需求模糊、边界不清的任务，不交给实现岗执行

## 🧩 岗位说明
- **实现岗**：接收明确、锁定边界的需求，专注交付产出；禁止主动拓展需求、追加额外内容
- **审查岗**：只做核验、排查幻觉、风险标记、输出问题清单，不负责重写内容
- **负责人（人）**：定义需求、划定验收标准、过滤AI自发新增需求、审阅审查结果、决定是否修改/定稿

## 📋 基础流转流程
1. 负责人明确需求、验收标准，划定任务边界
2. 下发需求给实现岗，产出初稿
3. 初稿交给独立审查岗，输出风险/问题清单
4. 负责人审阅清单，判断：驳回修改 / 直接定稿 / 补充需求
5. 如果需要修改，仅把精简的修改要点给到实现岗，不把完整审查报告全部灌入
6. 一轮闭环结束，按需重置会话，避免上下文无限累积

## 📌 关于大家关心的成本（重要声明）
使用这套框架，**并不保证自动省钱**。
在遵守框架规则、做好需求管控的前提下，会自然减少AI无意义发散、无效输出；搭配KV缓存、会话重置等工程手段可以进一步控制输入开销。
缓存策略、参数调优、模型选型、计费优化，都属于落地层的实操内容，交给使用者自行体验、调试。
如果任务规模扩大，审查环节也会产生相应开销。

## 🎯 适合谁
适合已经踩过AI幻觉、目标跑偏、Agent越跑越不受控的人；
想要建立稳定、可控的人机协作流程，而不是追求全自动、无人干预的智能流程。

## ⚠️ 免责与说明
- 本框架只是一套协作规则范式，不保证消除幻觉，风险最终仍由人把控
- 所有提示词、流程都可以自由裁剪改造，没有强制固定写法
- 欢迎交流思路、补充实践案例；不承诺适配所有业务场景
